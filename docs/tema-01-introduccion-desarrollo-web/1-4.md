# Actividad Práctica: Introducción al Patrón MVC y Protocolo HTTP

Esta actividad tiene como objetivo aplicar los conceptos teóricos aprendidos sobre la arquitectura Modelo-Vista-Controlador (MVC) y el funcionamiento del protocolo HTTP en el desarrollo de aplicaciones web.

---

## Descripción de la Tarea

La actividad consiste en analizar un escenario real de una aplicación web y desglosar cómo interactúan sus componentes siguiendo el flujo de trabajo del patrón MVC y las peticiones/respuestas HTTP.

### Escenario Propuesto:
Imagina una aplicación web de gestión de tareas (To-Do List). Un usuario autenticado entra a su panel principal y decide hacer clic en el botón **"Crear Nueva Tarea"** tras rellenar un formulario con el título *"Estudiar Laravel"* y la descripción *"Completar la unidad 1"*.

---

## Ejercicios a Desarrollar

Debes responder de forma razonada y estructurada a los siguientes puntos dentro de tu documentación:

### 1. Mapa del Flujo HTTP
Describe detalladamente todo el ciclo de vida de la petición desde que el usuario pulsa el botón hasta que vuelve a ver la pantalla actualizada:
* ¿Qué **método HTTP** y qué tipo de ruta crees que se debería utilizar para enviar el formulario? Explica por qué.
* Explica qué información viajaría en las **cabeceras (Headers)** y qué viajaría en el **cuerpo (Body)** de esa petición.
* ¿Qué **código de estado HTTP** debería devolver el servidor si la tarea se crea correctamente en el sistema?

### 2. División de Responsabilidades (MVC)
Identifica y explica qué parte de la aplicación se encargaría de cada acción basándote en las tres capas del patrón MVC:
* **El Controlador:** ¿Qué validaciones o comprobaciones iniciales debería hacer al recibir los datos del formulario antes de guardarlos?
* **El Modelo:** ¿Qué acciones realiza en este escenario? ¿Con qué elemento externo interactúa y para qué?
* **La Vista:** Una vez completado el proceso, ¿qué debe pintar o mostrar al usuario final en el navegador?

### 3. Simulación de Errores
Analiza qué ocurriría si las cosas no van bien en el servidor:
* Si el usuario intenta guardar la tarea pero la base de datos está caída o el código PHP tiene un fallo crítico, ¿qué **código de estado HTTP** se generaría?
* Si el usuario intenta acceder directamente a la ruta de creación de tareas sin haber iniciado sesión previamente, ¿qué código de error de la gama **4xx** sería el correcto para denegar el acceso?
